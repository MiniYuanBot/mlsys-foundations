## 研究训练问题

把残差加法和 RMSNorm 融合，能减少哪些临时张量和 kernel 启动？当行数很少或列数不整齐时，融合还有效吗？公开 OJ 有相关题目，但下面是课程自定义的小规模规格；提交平台前要按实际题面完成接口适配。

参考：[Triton Fused Softmax](https://triton-lang.org/main/getting-started/tutorials/02-fused-softmax.html) 的行归约结构、[Triton Layer Normalization](https://triton-lang.org/main/getting-started/tutorials/05-layer-norm.html) 的前向部分，以及 [LeetGPU 题库](https://leetgpu.com/challenges) 中 Fused Residual Add and RMS Norm。LayerNorm 会减均值，RMSNorm 本题不会；只借用分配工作与归约的思路。

### A 课内题

先做第1、2题，第3题选做。推导和画图可用纸笔或CPU脚本；这些草稿直接用于后面的实验，不另加一轮完整测量。

1. **【推导＋画图】尾部填充会怎样改变归一化？** 给定单行 `x=[1,-2,3,-4,5]`、`residual=[-1,1,1,2,-2]`、`gamma=[1,2,1,0.5,1]`、epsilon=`1e-5`，手算两个输出和平方和。把行补到8列，分别采用正确除数5和错误除数8，比较有效位置的结果。画出加载→残差相加→mask→平方和→归一化→双输出的流程图，在图上标明哪些值只在寄存器中存在、哪些必须写回。**交付：**逐步数值表、带形状的图、一个能检出错误除数的断言。参考 [Triton LayerNorm 前向与归约图](https://triton-lang.org/main/getting-started/tutorials/05-layer-norm.html)：借用归约组织方式，但本题RMSNorm不减均值，教程后半的反向归约图也不是本题前向实现。
2. **【定量计算】融合究竟少搬了多少数据？** 固定 `M=128,N=513`、FP32。比较四个独立kernel：①读x/residual、写z；②读z、写平方u；③读u、写每行一个归一化系数v；④读z/gamma/v、写y。假定每行读一次gamma，每行只读一次v并在行内复用；忽略缓存命中、地址计算和分配成本。再画单kernel的融合数据流，保留z、y两个输出。分别列出每条边的元素数、读写字节数与临时张量大小。以**教学假设**有效带宽200 GB/s、每次启动3 μs估算两种路径的时间，再将M改为1，判断哪项成本更重要。**交付：**两张数据流图和成本表；明确逻辑字节数为何不能直接当作DRAM计数器实测。对照 [Triton softmax 的访存分析与性能曲线](https://triton-lang.org/main/getting-started/tutorials/02-fused-softmax.html)，不要套用其算子的读写倍数。
3. **【选做：地址图】两种padding解决的是同一问题吗？** 在32个bank、每个32位字映射到一个bank的简化模型中，warp内线程t读取 `tile[t][0]`。分别令tile为FP32的32×32与32×33，列出32个地址和 `bank=word_address mod 32`，画线程→bank连线并计算额外shared memory。解释这种布局padding为何不能成为把RMSNorm除数从N改成BLOCK_SIZE的理由。参考 [NVIDIA转置教程的访存图](https://developer.nvidia.com/blog/efficient-matrix-transpose-cuda-cc/)；仅分析标量访问模型，不据此猜测Triton最终生成的指令。

### B 课内题

先做第1、2题，第3题选做。题中计时数据是教学数据，不能放入自己的真实性能报告。

1. **【细节复现】找出“缩放不变”何时失效。** 复用A1输入，同时把x与residual乘以 `a∈{0.001,1,1000}`。在epsilon固定为 `1e-5` 时，推导向量关系 `y(a)=r(a)y(1)`，并用CPU浮点参考核对：非零坐标比较比例，零坐标检查仍为零，避免计算0/0。再说明epsilon为0、行非零时的理想式与实际实现有何差别。补全零行、gamma全零、N=1和N=513的检查，验证两个输出都正确且输入未被修改。**交付：**公式、误差随a变化的图和测试说明；区分精确性质与需容差的浮点比较。
2. **【定量＋画图】最快配置是否依赖工作负载？** 两种输入的教学耗时如下，单位μs：小形状 `(1,513)` 的eager/warp4/warp8为 `16/8/10`，大形状 `(128,513)` 为 `40/20/16`。设大形状请求占比p、每请求只执行一次算子，先写warp4和warp8的期望耗时，求配置优劣改变的p，再画p从0到1的耗时曲线。用p=0.1和0.9比较“按请求比例(1-p,p)加权的逐请求加速比均值”与“同一请求集合总耗时比”。**交付：**交点、两种统计口径、开发集如何选配置及留出集如何避免泄露的规则；不能用这两个点断言其他形状也成立。
3. **【选做：线程图复现】一棵归约树如何处理非整齐长度？** 用8个线程规约5个元素，画每一轮哪些线程读写哪些槽位、何处需要同步；再把两块局部和合成一个全局结果。禁止让无效线程在本块其他线程仍需同步时提前退出。对照 [GPU Puzzles 的 Shared、Sum 与 Axis Sum 图示](https://github.com/srush/GPU-Puzzles)，用顺序CPU模拟检查每轮数组，或在已有环境里做可视化。**交付：**分轮状态图与元素守恒检查。Notebook执行需要其Numba/CUDA环境，查看图和完成CPU模拟不要求额外安装；模拟的访存次数不是GPU耗时。

## 本地完整规格

输入：contiguous 的 `x,residual:[M,N]` 和 `gamma:[N]`，默认均为 FP32；epsilon=1e-5。输出两个独立张量 `z,y:[M,N]`，均为 FP32，不修改输入。只做 forward、no_grad。

令 `z = x + residual`，每行归一化为：

$$y_{ij}=z_{ij}\;\bigl(\frac{1}{N}\sum_{k=1}^{N}z_{ik}^{2}+10^{-5}\bigr)^{-1/2}\;\gamma_j.$$

归约的除数是实际 N，不是 padding 后的 BLOCK_SIZE。无效列对平方和的贡献必须是 0。既然接口要求输出 z，融合后仍要写出 z；不能通过少交一个输出来制造加速。

三个版本：A，朴素 PyTorch eager 参考；B，正确的初版 Triton 融合 kernel；C，对 B 做一项改变后的版本。默认只将 `num_warps` 从 4 改为 8；若采用别的变化，需在运行前写清并保留 B。只比较 A/B 也有价值，但 C 未完成时增强验收标待补，不将两份相同代码当消融。

开发矩阵 M∈{1,128}、N∈{128,513,1024}，共 6 形状。seed=42，x/residual 为标准正态，gamma 在 [0.5,1.5] 均匀生成。每个实现使用相同输入，每形状三轮，共 54 条计时记录。按 lab1 的 20 次预热、100 次内部迭代与同步方法测量；编译成本另列，两个输出都必须被计算并保留到调用结束。

留出矩阵为 (7,257)、(7,1537)，seed=2026。根据开发矩阵确定配置后，再运行三版本各三轮，共 18 条；看完留出结果后再调整就属于下一轮开发，不能继续称它为未参与调参的测试。各形状单列，不凭少量数据推断普遍规律。

## 必须通过的检查

1. 开发与留出形状的 z/y 与独立参考比较，起点 `rtol=1e-4, atol=1e-5`，分别保存最大绝对误差。失败先检查实际 N、mask、缩放与精度，不直接放宽阈值。
2. `x=-residual` 时，z/y 都应为 0；epsilon 防止分母为 0。
3. gamma 全零时 y 为零，但 z 仍正确；这能发现只顾主输出的错误实现。
4. N=1 时，与标量公式 `z/sqrt(z*z+epsilon)*gamma` 核对；它一般不等于 z 或常数 1。
5. 输入同时取反时，z/y 同时取反；输入有限且本周幅度范围适当时输出应有限。使用独立新样本做此检查，不宣称覆盖所有浮点特殊值。
6. 保存调用前的 x/residual/gamma 副本，确认没有被原位覆盖。

- [ ] 开发与留出结果分开，保存变慢的形状及轮间波动。
- [ ] 解释至少一个额外启动/内存读写的来源；没有 profiler 时不把估算流量当实测。

有余力再选**一项**：FP16 输入、FP32 累加、最后转回 FP16；更大列宽；或跨 GPU 外部有效性。FP16 版本先明确 residual 相加何时舍入、归一化使用舍入前还是舍入后 z，参考实现保持一致。每项另计 2–5h，属于后续练习。
