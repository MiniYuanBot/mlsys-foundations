# lab7 自评分（100 分）

基础练习的环境与评分见本目录；系统任务见 [systems.md](systems.md)，研究拓展见 [research.md](research.md)。

依据 [课程 lab7-proposal.md](../../mlsys-research-course/labs/lab7-proposal.md)；规则见 [全局测试与评分](../docs/grading.md)。不按加速比奖励分数，负结果也可满分。

| ID | 类型 | 分值 | 必过线 | 验收依据 |
|---|---|---:|---:|---|
| holdout | 自动 | 10 | 10 | `lab7.tests.Holdout`：继承 lab6 控制、仅输入长度变化、上下文降级合法 |
| holdout_evidence | 人工自评 | 30 | 30 | **预定义留出与证据**：测量前固定预测/指标/新条件（10）；12 次原始请求与旧 rate/N/SLO、长输入实际长度（15）；支持/反驳/不足结论及过载边界（5）。 |
| proposal | 人工自评 | 35 | 25 | **两页提案**：1200–1800 字与实测主图（10）；最近三项工作的具体重合/差异与链接（10）；两周至少六任务，输入/输出/预算/卡点/停止条件（10）；事实/推断/假设/计划区分（5）。 |
| portfolio | 人工自评 | 25 | 15 | **结课包与汇报**：首页可找到环境、6–8 阅读卡、论文地图、各 lab 证据、提案/机制报告（15）；10 分钟汇报提纲、贡献/AI 说明及向导师的具体问题（10）。 |

自动组内全部检查通过才得该组分数；skip、异常、零测试不算通过。人工项按表内子项累加，证据不齐时不给相应分数。所有必过线达到且总分 ≥80 才输出 `self-assessed-pass`；80–89 基础完成，90–100 证据较完整，<80 待补。自动测试只证明覆盖的行为，不能代替真实实验或口头理解。

从项目根目录运行：

```bash
python -m unittest lab7.tests -v
python -m tools.grade lab7
```

复制 `assessment.example.json` 为本章 `assessment.json`，补分数、逐项核对说明和相对项目根目录的非空证据文件路径，再运行：

```bash
python -m tools.grade lab7 --assessment lab7/assessment.json
```

第一次运行出现未实现失败或环境阻塞是预期；不要改测试来获得分数。机器检查证据存在，但**不能判断论文、日志或图是否真实/合格**，人工分会单独标记。单纯拿本仓库的空报告模板作为 evidence 不符合自评规则。报告写入 `results/grades/lab7.json`，包含每组测试详细日志。

选做增强/OJ 状态单独记录在报告中，不加入主线 100 分，也不成为下一章的隐含门槛。
