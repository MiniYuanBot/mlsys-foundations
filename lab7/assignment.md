# 方法练习：更长输入下的留出验证

运行环境：WSL2/CUDA 服务 + 文献分析。以下命令均在项目根目录执行。

## 实验任务

你要预先写新条件预测、补 `plan.build_matrix`，复用原工具执行，再写提案和结课包。分析结论与研究问题需根据自己的实验提出。先看[提案](proposal.md)、[汇报提纲](talk.md)和[结课入口](../portfolio/README.md)。

## 留出实验

默认只把lab6输入1024改1536，输出64，仍budget512/2048、旧low/high、旧N/SLO、三个seed、同区组顺序，共12次。上下文1536时选1408，1024时前章768→本章896。heldout>上一章且input+64≤context。冻结design已有这两列；不要看新结果后改rate或主指标。

```bash
python -m unittest lab7.tests -v
python -m lab3.commands --config lab3/service.json --lab lab7 --design results/lab4/design.json --out results/lab7/plan
```

生成器复用lab6重启/预热模板；每次重启8个**新长度**请求预热。事先保存预测与判据，按矩阵执行，逐轮转换/汇总，与lab6按seed/rate/budget配对比较。新条件高rate过载是边界证据；若要降rate，另开整组A/B后续实验，不覆盖原主对照。

## 分析与报告

回答五问：旧趋势延续吗；何处反转；现有工作是否已预期；当前缺机制/负载/模型/可靠测量哪项；下一项最小证据如何决定继续或停止。

提案1200–1800中文字、一张实测主图、最接近三工作及具体重合/差异。句子区分事实/推断/假设/计划。未来两周至少六项具体任务，各写输入/输出/时间/卡点/判定；第一项能在现有资源执行。未找到缺口就写性能边界调查计划，不把未查到等同不存在。

交付12次新条件证据、分析脚本/图、提案、6–8阅读卡与论文地图、10分钟汇报提纲、个人贡献说明、导师一个具体判断请求。首页应能找到每项真实文件/归档位置。

增强30分钟：请AI提出三个反驳，逐项回到原文/数据核查，将最有力的一条变成最小后续任务；不能为了完成作业硬编一个错误反驳。
